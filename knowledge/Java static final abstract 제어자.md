[[Java 접근 제어자|접근 제어자]] 외에, Object Modeling에서 **특별한 기능을 하는** 제어자들이다.

![[java-other-modifier.png]]

## static — 공통으로 같이 쓰는 것
객체는 저마다 다른 상태값을 가진다는 원칙을 **의도적으로 깨는** 제어자다. 남고 학생들의 성별, 대한민국 사람의 국적처럼 **공통·공공의 성격**을 가진 값에 쓴다.

- static 변수는 ==static 메모리 공간에 따로 저장==된다 → **인스턴스 안에서 바뀐 값과는 전혀 무관하다**
- 저장될 때 다른 클래스와 혼선을 막기 위해 **클래스 이름을 함께 저장**한다
- 그래서 생성자 없이 클래스 이름으로 바로 호출할 수 있다

![[java-static-memory.png]]

```java
Math.PI;  Math.max();  Math.min();   // 인스턴스 생성 없이 호출
```

> [!tip]
> **상태를 변화시키는 메서드가 아니라면 `static`으로 선언한다.** 쓸 때마다 생성자를 만들 필요가 없어진다.

## final — 여기서 끝
"마지막의, 더 변경될 수 없는 것"이라는 뜻으로, **계층화를 포기**한다는 선언이다.

> **클래스는 더 이상 확장하지 말고, 필드 값은 변경할 수 없으며, 메서드는 오버라이딩하지 말아라.**

상수 이름은 관례상 Snake case(대문자 + 언더스코어)를 쓴다.

## abstract — 선언만, 구현은 비운다
"구체적일 필요가 없는", 즉 **상속받은 하위 클래스에서 구체적으로 재정의되어야 하는** 것에 붙인다.

```java
// 추상 메서드를 포함한 추상 클래스 — 인스턴스 생성 불가
abstract class A {
    abstract void move();   // 구현부가 없다
}
```

- 하위 클래스는 **반드시 오버라이딩해 재정의**해야 한다
- 단, **자신도 abstract 클래스로 선언하면** 오버라이딩을 미룰 수 있다
